# ArtSurv - Life Simulation Game

> **Масштаб проекта**: ~1.5 GB данных (включая ассеты), 100+ модулей логики, 50+ компонентов UI.
> **Архитектура**: Data-Driven Design с четким разделением на слои данных, логики и представления.

## 🎮 О проекте

**ArtSurv** - это образовательная игра-симулятор жизни, которая учит игроков принимать сбалансированные решения с долгосрочными последствиями.

**Цель проекта**: Предоставить игрокам безопасное пространство для "проживания" жизни в игре, где они могут:

- Экспериментировать с финансовыми, карьерными и жизненными решениями
- Учиться жить сбалансированно и выполнять действия с долгосрочной перспективой
- Получать инсайты о взаимосвязи краткосрочных выгод и долгосрочных последствий

### 🎯 Ключевая философия игры:

> **"Дешевая еда повышает счастье сегодня, но снижает здоровье завтра"**

Игра демонстрирует, как краткосрочные решения влияют на долгосрочное благополучие.

## 🛠 Разработка и Качество (CI/CD)

В проекте настроена автоматическая проверка качества кода на нескольких уровнях.

### Единая команда проверки

Для запуска всех проверок (линтинг, типы, архитектура, тесты, дубликаты, форматирование) используйте:

```bash
pnpm check-all
```

Эта команда последовательно запускает:

1. `pnpm lint` — статический анализ кода (ESLint).
2. `pnpm typecheck` — проверка типизации (TypeScript).
3. `pnpm arch:check` — проверка архитектурных правил и зависимостей (Dependency Cruiser).
4. `pnpm test` — запуск юнит-тестов (Vitest).
5. `pnpm dry:check` — поиск дублирования кода (jscpd, порог 3%).
6. `pnpm format:check` — проверка стиля кода (Prettier).

### Проверка архитектуры

Мы используем **Dependency Cruiser** для контроля архитектурных границ. Правила описаны в `.dependency-cruiser.cjs`.
Проверка помогает избежать:

- Циклических зависимостей.
- Использования модулей, которые не должны быть доступны в определенных частях приложения.
- Нарушения слоистой архитектуры.

Запустить отдельно:

```bash
pnpm arch:check
```

### Автоматизация (Git Hooks)

Мы используем **Husky** для автоматического запуска проверок:

- **pre-commit**: Запускает `lint-staged` (ESLint и Prettier только для измененных файлов).
- **commit-msg**: Проверяет формат сообщения коммита (используется `commitlint` и стандарт **Conventional Commits**).
- **pre-push**: Запускает проверку типов (`tsc --noEmit`).

### CI/CD

При каждом push или pull request в ветки `main`, `master` или `dev` запускается GitHub Actions workflow, который:

1. Устанавливает зависимости.
2. Выполняет `pnpm check-all`.
3. Собирает проект (`pnpm build`).
