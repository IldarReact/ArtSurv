# 🧠 Logic Architecture Documentation

## Обзор

Система логики в ArtSurv построена на архитектуре **"Turn-based Pipeline"** (Пошаговый конвейер). Это позволяет изолировать логику обработки хода от состояния UI и хранилища, делая систему предсказуемой и легко тестируемой.

Основная цель этой системы — взять текущее состояние игры (`GameStore`), провести серию вычислений (симуляция хода) и вернуть обновленное состояние.

## 📁 Структура

Логика сосредоточена в директории `core/model/logic/` и делится на следующие компоненты:

### 1. 🎼 Orchestrator (`turn/turn-orchestrator.ts`)

Центральный контроллер, который управляет процессом обработки хода.

- **Функция**: `processTurn(get, set)`
- **Процесс**:
  1.  Получает текущий стейт (`get()`).
  2.  Создает неизменяемый контекст (`TurnContext`).
  3.  Инициализирует изменяемое состояние хода (`TurnState`).
  4.  Последовательно запускает все шаги (`STEPS`).
  5.  Коммитит изменения обратно в стейт (`set(...)`).

### 2. 📦 Context & State (`turn/`)

Разделение данных на "что было" и "что происходит сейчас".

- **TurnContext** (`turn/turn-context.ts`):
  - _Immutable_. Содержит ссылку на предыдущий стейт (`prev`), номер текущего хода и год.
  - Используется только для чтения данных, чтобы избежать побочных эффектов от изменения исходного стейта во время расчетов.

- **TurnState** (`turn/turn-state.ts`):
  - _Mutable_. Рабочий объект, который передается по цепочке шагов.
  - Содержит промежуточные вычисления (например, `moneyDelta`, `business.totalIncome`) и обновленные версии объектов (игрок, страны).
  - Инициализируется в `initTurnState` (`turn/init-turn-state.ts`), который создает "снимок" данных для обработки.

### 3. 👣 Steps (`steps/`)

Изолированные модули логики, каждый из которых отвечает за свой домен.

- **Тип**: `TurnStep = (ctx: TurnContext, state: TurnState) => void`
- **Принцип**: Шаг читает данные из `ctx` или `state`, производит вычисления и **мутирует** `state`.
- **Порядок выполнения** (определен в `turn/turn-step.ts`):
  1.  `economyStep` — макроэкономика и события.
  2.  `marketStep` — рыночные изменения.
  3.  `educationStep` — прогресс обучения.
  4.  `jobsStep` — работа и зарплата.
  5.  `businessStep` — расчет прибыли бизнесов.
  6.  `buffsStep` — временные эффекты.
  7.  `lifestyleStep` — расходы на жизнь.
  8.  `thresholdsStep` — проверка пороговых значений статов.
  9.  `financialStep` — итоговый финансовый отчет.
  10. `inflationStep` — инфляция (раз в год).

### 4. 💾 Commit (`turn/commit-turn.ts`)

Финальный этап, который преобразует `TurnState` в патч для глобального `GameStore`.

- Собирает все изменения воедино.
- Применяет финансовые дельты.
- Обновляет мета-данные (номер хода, год).
- Формирует список уведомлений.

## ⚙️ Общие Механики

### Пошаговый Прогресс (Progressable)

Для унификации механик, которые выполняются в течение нескольких ходов (обучение, фриланс-заказы, проекты), используется единая система прогресса.

- **Интерфейс `Progressable`** (`core/types/progress.types.ts`):
  - `id`: Уникальный идентификатор.
  - `title`: Название (для отображения).
  - `totalDuration`: Общая длительность в ходах.
  - `remainingDuration`: Сколько ходов осталось.
  - `costPerTurn`: (Опционально) Эффекты на статы игрока каждый ход (энергия, деньги и т.д.).

- **Процессор `processProgress`** (`core/lib/progress/progress-processor.ts`):
  - Универсальная функция, которая:
    1. Уменьшает `remainingDuration` на 1.
    2. Разделяет список объектов на `active` (те, что продолжаются) и `completed` (те, что завершились в этом ходу).

- **Где используется**:
  - `ActiveCourse` (Курсы обучения)
  - `ActiveUniversity` (Университетские программы)
  - `ActiveFreelanceGig` (Фриланс-заказы)
  - `TimedBuff` (Временные эффекты/баффы)
  - `openingProgress` (Прогресс открытия бизнеса)
  - `Pregnancy` (Беременность)

## 🔄 Поток данных (Data Flow)

```mermaid
graph TD
    A[GameStore (Prev)] -->|Read| B(TurnContext)
    A -->|Clone/Init| C(TurnState)
    B --> D{Pipeline Loop}
    C --> D

    D -->|Mutate| E[Step 1: Economy]
    E -->|Mutate| F[Step 2: Business]
    F -->|Mutate| G[Step N: ...]

    G --> H[Commit Turn]
    H -->|Patch| I[GameStore (Next)]
```

## 🧩 Примеры реализации

### Economy Step

Обрабатывает экономические циклы и глобальные события.

- Использует: `processEconomicCycle`
- Результат: Обновляет `state.country`, `state.globalMarketValue` и добавляет уведомления.

### Business Step

Рассчитывает доходность предприятий игрока.

- Делегирует сложную логику в `processBusinessTurn`.
- Результат: Обновляет `state.player.businesses`, `state.business.totalIncome`, списывает энергию/рассудок игрока за управление.

## 📝 Контекст проекта (из README)

Проект **ArtSurv** — это образовательный симулятор жизни, где важен баланс между краткосрочными выгодами и долгосрочными последствиями.
Логика хода (`Turn Logic`) является сердцем симуляции ("Game Loop"), где раз в квартал (1 ход) происходят все ключевые пересчеты:

- Инфляция (раз в год).
- Влияние статов на жизнь (здоровье, счастье).
- Финансовые итоги (доходы/расходы).

Архитектура позволяет легко добавлять новые механики, просто создавая новый `Step` и добавляя его в массив `STEPS`.
